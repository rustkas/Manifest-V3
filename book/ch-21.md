# Часть VIII. Commands и управление расширением

# Глава 21. Commands

Keyboard shortcuts — один из наиболее мощных механизмов управления браузерным расширением.

Пользователь может запускать действие extension не через:

```text
Extension icon
    ↓
Popup
    ↓
Button
```

а непосредственно с клавиатуры:

```text
Keyboard
    ↓
Command
    ↓
Extension
```

Для небольших расширений это просто удобный shortcut.

Для сложного расширения commands могут стать полноценным **keyboard interface** приложения.

Например:

```text
Ctrl + Shift + A
        ↓
Analyze current page
```

или:

```text
Alt + Shift + S
        ↓
Open Side Panel
```

или:

```text
Ctrl + Shift + Y
        ↓
Extract selected text
```

---

# 21.1. Keyboard shortcuts

В Manifest V3 команды описываются в `manifest.json` через поле:

```json
{
    "commands": {
        "command_name": {
            "suggested_key": {
                "default": "Ctrl+Shift+A"
            },
            "description": "Analyze current page"
        }
    }
}
```

Здесь:

```text
commands
   │
   └── command_name
           │
           ├── suggested_key
           │
           └── description
```

---

# Что такое command

Command — это не JavaScript-функция.

Это **идентификатор пользовательского действия**, зарегистрированный extension.

Например:

```text
analyze-page
open-side-panel
save-selection
toggle-extension
```

Manifest связывает command с клавишами:

```text
Keyboard shortcut
       ↓
Command ID
       ↓
Extension handler
```

---

# Command ID

Например:

```json
{
    "commands": {
        "analyze-page": {
            "suggested_key": {
                "default": "Ctrl+Shift+A"
            },
            "description": "Analyze current page"
        }
    }
}
```

Здесь:

```text
analyze-page
```

— это идентификатор команды.

JavaScript получит именно его.

---

# Shortcut не является самой командой

Важно разделять:

```text
Shortcut
```

и:

```text
Command
```

Shortcut:

```text
Ctrl + Shift + A
```

Command:

```text
analyze-page
```

Поэтому архитектура:

```text
Ctrl+Shift+A
      ↓
analyze-page
      ↓
handler
```

Это позволяет отделить пользовательское управление от реализации.

---

# Keyboard shortcut как input event

Можно рассматривать command как ещё один источник событий:

```text
                         Extension
                            │
       ┌────────────────────┼────────────────────┐
       │                    │                    │
       ▼                    ▼                    ▼
     Action              Command              Message
       │                    │                    │
       └────────────────────┼────────────────────┘
                            ▼
                     Application logic
```

Таким образом, команда не должна содержать всю бизнес-логику.

Она должна **запустить действие**.

---

# 21.2. `commands` в manifest

Рассмотрим полный пример.

```json
{
    "manifest_version": 3,

    "name": "Page Assistant",
    "version": "1.0.0",

    "permissions": [
        "activeTab"
    ],

    "commands": {
        "analyze-page": {
            "suggested_key": {
                "default": "Ctrl+Shift+A"
            },
            "description": "Analyze current page"
        },

        "open-panel": {
            "suggested_key": {
                "default": "Ctrl+Shift+P"
            },
            "description": "Open side panel"
        }
    }
}
```

Теперь extension зарегистрировал две команды:

```text
Ctrl+Shift+A
      ↓
analyze-page
```

и:

```text
Ctrl+Shift+P
      ↓
open-panel
```

---

# `suggested_key`

Поле:

```json
"suggested_key": {
    "default": "Ctrl+Shift+A"
}
```

задаёт рекомендуемую комбинацию клавиш.

Важно слово **suggested**.

Это не означает, что браузер гарантирует именно эту комбинацию пользователю во всех обстоятельствах.

Пользовательские настройки браузера и конфликты shortcuts могут изменить фактическое назначение.

---

# Платформы

Можно задавать разные комбинации для разных платформ:

```json
{
    "suggested_key": {
        "default": "Ctrl+Shift+A",
        "mac": "Command+Shift+A"
    }
}
```

Например:

```text
Windows / Linux
Ctrl + Shift + A

macOS
Command + Shift + A
```

Это особенно важно для cross-platform extensions.

---

# `description`

```json
"description": "Analyze current page"
```

Описание объясняет пользователю назначение команды.

Оно также помогает браузеру отображать command в интерфейсе управления shortcuts.

Описание должно быть коротким и понятным:

Хорошо:

```text
Analyze current page
```

Плохо:

```text
Execute the primary page analysis
functionality of the extension
```

---

# Команда без shortcut

Можно зарегистрировать command без предлагаемого shortcut.

Например:

```json
{
    "commands": {
        "analyze-page": {
            "description": "Analyze current page"
        }
    }
}
```

Такой command может использоваться как зарегистрированное действие, но пользовательская клавиатурная комбинация для него не обязательно будет назначена.

---

# Максимум и ограничения

Не следует проектировать extension вокруг предположения:

> «Я могу назначить любое количество произвольных комбинаций клавиш».

Браузер имеет собственные ограничения на commands и shortcut configuration.

Поэтому при проектировании:

```text
commands
```

нужно выбирать только действительно важные действия.

---

# Хорошие кандидаты для commands

Обычно shortcut стоит давать действиям, которые пользователь выполняет часто.

Например:

```text
Open Side Panel
Analyze page
Save selection
Toggle feature
Search extension
Capture information
```

---

# Плохие кандидаты

Не стоит создавать shortcut для каждой кнопки интерфейса:

```text
open-settings
open-help
change-theme
change-font
delete-item
rename-item
...
```

Это быстро превращает keyboard interface в хаос.

---

# 21.3. Command handlers

После регистрации command необходимо обработать его в extension.

Для этого используется:

```javascript
chrome.commands.onCommand
```

Например:

```javascript
chrome.commands.onCommand.addListener(
    (command) => {

        console.log(
            "Command:",
            command
        );

    }
);
```

Обычно такой handler размещается в Service Worker.

---

# Простой пример

```javascript
chrome.commands.onCommand.addListener(
    async (command) => {

        if (command === "analyze-page") {

            console.log(
                "Analyze current page"
            );
        }
    }
);
```

Теперь:

```text
Ctrl+Shift+A
      ↓
analyze-page
      ↓
onCommand
      ↓
handler
```

---

# Command handler как router

Лучше не создавать большой `if`-блок.

Можно использовать routing table:

```javascript
const commands = {
    "analyze-page": analyzePage,
    "open-panel": openPanel,
    "save-selection": saveSelection
};

chrome.commands.onCommand.addListener(
    async (command) => {

        const handler =
            commands[command];

        if (!handler) {
            return;
        }

        await handler();
    }
);
```

Теперь architecture:

```text
Command
   ↓
Router
   ↓
Handler
```

---

# Почему Service Worker — естественное место

Commands являются browser-level events.

Service Worker как раз предназначен для обработки событий extension:

```text
Action
Commands
Tabs
Windows
Alarms
Runtime
Messages
```

Поэтому:

```text
Browser
   ↓
Command
   ↓
Service Worker
```

является естественной архитектурой.

---

# Command → application action

Не следует делать:

```javascript
chrome.commands.onCommand.addListener(
    async (command) => {

        // 300 lines of application logic

    }
);
```

Лучше:

```javascript
chrome.commands.onCommand.addListener(
    async (command) => {

        await dispatchCommand(command);

    }
);
```

А уже:

```javascript
async function dispatchCommand(command) {

    switch (command) {

        case "analyze-page":
            return analyzeCurrentPage();

        case "open-panel":
            return openSidePanel();

    }
}
```

---

# Command handler должен быть thin

Хорошая архитектура:

```text
Command
   ↓
Handler
   ↓
Application Service
   ↓
Business Logic
```

а не:

```text
Command
   ↓
Huge Handler
   ↓
Everything
```

---

# 21.4. Browser shortcut conflicts

Это один из наиболее важных практических вопросов.

Вы можете написать:

```json
"suggested_key": {
    "default": "Ctrl+Shift+A"
}
```

но это не означает:

> «Теперь Ctrl+Shift+A всегда принадлежит моему extension».

Браузер и операционная система имеют собственные shortcut mechanisms.

Кроме того, пользователь может уже использовать эту комбинацию.

---

# Что происходит при конфликте

Условно:

```text
Extension:
Ctrl+Shift+A
       │
       │ conflict
       ▼
Browser / OS / another command
```

Поэтому extension не должен предполагать, что shortcut всегда будет доступен.

---

# Пользовательские shortcuts

В Chrome пользователь может управлять keyboard shortcuts расширений через страницу:

```text
chrome://extensions/shortcuts
```

Это позволяет пользователю:

* изменить shortcut;
* удалить shortcut;
* назначить другую комбинацию.

Поэтому application code не должен зависеть от конкретной комбинации.

Он должен зависеть от:

```text
command ID
```

а не:

```text
Ctrl+Shift+A
```

---

# Правильная абстракция

Плохо:

```javascript
if (key === "Ctrl+Shift+A") {
    analyze();
}
```

Хорошо:

```javascript
if (command === "analyze-page") {
    analyze();
}
```

Shortcut — configuration.

Command — semantic action.

---

# Почему это особенно важно

Пользователь может изменить:

```text
Ctrl+Shift+A
```

на:

```text
Alt+Shift+X
```

Но extension должен продолжать работать:

```text
Alt+Shift+X
      ↓
analyze-page
      ↓
analyze()
```

---

# Cross-platform design

Не стоит проектировать бизнес-логику вокруг Windows-specific shortcut semantics.

Например:

```text
Windows:
Ctrl

macOS:
Command
```

Manifest может задавать platform-specific suggestions.

Но application layer работает с:

```text
analyze-page
```

---

# Shortcut discoverability

Keyboard-driven UX имеет одну проблему:

> Пользователь может не знать о существовании shortcuts.

Поэтому хорошее расширение может показывать:

```text
Analyze page
Ctrl+Shift+A
```

в UI.

Но не следует жёстко вшивать shortcut в интерфейс как гарантированную комбинацию.

Лучше воспринимать его как текущую настройку пользователя.

# 21.5. Context-aware commands

Теперь рассмотрим более сложный сценарий.

Пользователь находится на разных страницах:

```text
example.com
github.com
docs.example.com
```

Одна и та же команда может иметь различное поведение.

Например:

```text
Ctrl+Shift+A
```

на обычной странице:

```text
Analyze page
```

на GitHub:

```text
Analyze repository
```

---

# Command ≠ fixed implementation

Command определяет намерение:

```text
analyze-page
```

а context определяет реализацию:

```text
current tab
current URL
selected text
page state
extension state
```

Архитектура:

```text
Command
   ↓
Current Context
   ↓
Application Action
```

---

# Получение текущей вкладки

Service Worker:

```javascript
async function getActiveTab() {

    const [tab] =
        await chrome.tabs.query({
            active: true,
            currentWindow: true
        });

    return tab;
}
```

Затем:

```javascript
async function analyzeCurrentPage() {

    const tab =
        await getActiveTab();

    if (!tab?.id) {
        return;
    }

    console.log(
        "Analyze:",
        tab.url
    );
}
```

---

# Context-aware routing

Например:

```javascript
async function analyzeCurrentPage() {

    const tab =
        await getActiveTab();

    if (!tab?.url) {
        return;
    }

    const url =
        new URL(tab.url);

    if (url.hostname === "github.com") {

        return analyzeGitHub(tab);

    }

    return analyzeGenericPage(tab);
}
```

Получаем:

```text
Ctrl+Shift+A
      ↓
analyze-page
      ↓
active tab
      ↓
┌───────────────┐
│ Context       │
├───────────────┤
│ GitHub        │ → GitHub analyzer
│ Documentation │ → Docs analyzer
│ Generic page  │ → Generic analyzer
└───────────────┘
```

---

# Context может включать selection

Ещё интереснее — команда может работать с выделенным текстом.

Например:

```text
User selects text
       ↓
Ctrl+Shift+A
       ↓
Analyze selection
```

Content Script может получить selection:

```javascript
const selection =
    window.getSelection()?.toString();
```

Затем:

```javascript
chrome.runtime.sendMessage({
    type: "ANALYZE_SELECTION",
    text: selection
});
```

---

# Но command не знает DOM

Service Worker не находится в DOM страницы.

Поэтому:

```text
Command
   ↓
Service Worker
   ↓
Content Script
   ↓
DOM
```

если команде требуется информация со страницы.

---

# Context-aware architecture

Можно построить:

```text
                  Command
                     │
                     ▼
              Service Worker
                     │
             ┌───────┴────────┐
             ▼                ▼
        Tab context       Extension state
             │
             ▼
       Content Script
             │
             ▼
             DOM
```

# 21.6. Commands → Content Script

Рассмотрим типичный сценарий.

Пользователь нажимает:

```text
Ctrl+Shift+H
```

Команда:

```text
highlight-headings
```

Service Worker получает событие.

```text
Command
   ↓
Service Worker
   ↓
Content Script
   ↓
DOM modification
```

---

# Отправка сообщения

Например:

```javascript
chrome.commands.onCommand.addListener(
    async (command) => {

        if (
            command !==
            "highlight-headings"
        ) {
            return;
        }

        const [tab] =
            await chrome.tabs.query({
                active: true,
                currentWindow: true
            });

        if (!tab?.id) {
            return;
        }

        await chrome.tabs.sendMessage(
            tab.id,
            {
                type: "HIGHLIGHT_HEADINGS"
            }
        );
    }
);
```

Content Script:

```javascript
chrome.runtime.onMessage.addListener(
    (message) => {

        if (
            message.type ===
            "HIGHLIGHT_HEADINGS"
        ) {

            highlightHeadings();
        }
    }
);
```

---

# Важный lifecycle issue

Content Script может отсутствовать.

Например:

```text
chrome://...
extension page
restricted page
page not yet loaded
```

Поэтому нельзя считать:

```javascript
chrome.tabs.sendMessage(...)
```

гарантированно успешным.

Нужно обрабатывать ошибку.

---

# Надёжная архитектура

Например:

```javascript
try {

    await chrome.tabs.sendMessage(
        tab.id,
        {
            type: "HIGHLIGHT_HEADINGS"
        }
    );

} catch (error) {

    console.error(
        "Content script unavailable",
        error
    );
}
```

Но ещё лучше архитектурно заранее понимать:

```text
Can content script run here?
```

---

# Programmatic injection

Если архитектура требует выполнения Content Script только после command, можно использовать programmatic injection через `chrome.scripting`.

Например:

```javascript
await chrome.scripting.executeScript({
    target: {
        tabId: tab.id
    },
    files: [
        "content.js"
    ]
});
```

Для этого потребуются соответствующие permissions/host access.

Таким образом:

```text
Command
   ↓
Service Worker
   ↓
scripting.executeScript()
   ↓
Content Script
```

# 21.7. Commands → Service Worker

Самый простой вариант:

```text
Keyboard
   ↓
Command
   ↓
Service Worker
```

Например:

```javascript
chrome.commands.onCommand.addListener(
    async (command) => {

        if (
            command === "open-panel"
        ) {
            await openPanel();
        }
    }
);
```

---

# Command → Side Panel

Команда может использоваться для запуска Side Panel.

Например:

```text
Ctrl+Shift+P
      ↓
open-panel
      ↓
Service Worker
      ↓
Side Panel
```

Service Worker:

```javascript
chrome.commands.onCommand.addListener(
    async (command) => {

        if (
            command !== "open-panel"
        ) {
            return;
        }

        const [tab] =
            await chrome.tabs.query({
                active: true,
                currentWindow: true
            });

        if (!tab?.windowId) {
            return;
        }

        await chrome.sidePanel.open({
            windowId: tab.windowId
        });
    }
);
```

---

# Command → Storage

Command может менять persistent state.

Например:

```text
Ctrl+Shift+B
      ↓
toggle-blocking
      ↓
Service Worker
      ↓
chrome.storage
```

```javascript
async function toggleBlocking() {

    const result =
        await chrome.storage.local.get({
            enabled: false
        });

    await chrome.storage.local.set({
        enabled: !result.enabled
    });
}
```

---

# Command → Tabs

Например:

```text
Ctrl+Shift+N
      ↓
open-dashboard
      ↓
tabs.create()
```

```javascript
await chrome.tabs.create({
    url: chrome.runtime.getURL(
        "dashboard.html"
    )
});
```

Таким образом command может управлять browser state.

# Command → Application Router

Для большого extension лучше иметь единый command dispatcher:

```text
                      Keyboard
                         │
                         ▼
                    Command API
                         │
                         ▼
                  Command Router
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
      Side Panel      Content Script   Storage
          │              │              │
          └──────────────┼──────────────┘
                         ▼
                  Application State
```

# 21.8. UX keyboard-driven extensions

Теперь самое важное.

Commands — это не просто технический API.

Это способ проектирования пользовательского интерфейса.

У extension может существовать два UI:

```text
Mouse UI
    │
    ├── Action
    ├── Popup
    └── Side Panel

Keyboard UI
    │
    └── Commands
```

---

# Keyboard-first extension

Некоторые extensions могут быть ориентированы прежде всего на клавиатуру.

Например:

```text
Ctrl+Shift+P
    ↓
Command palette
```

Пользователь вводит:

```text
> analyze
> translate
> save
> summarize
```

и выбирает действие.

Это уже напоминает IDE.

---

# Command Palette

Архитектурно:

```text
Keyboard
   ↓
Command
   ↓
Side Panel / Extension Page
   ↓
Command Palette
   ↓
Action
```

Например:

```text
┌───────────────────────────────┐
│ > summarize                   │
├───────────────────────────────┤
│ Summarize page                │
│ Summarize selection           │
│ Summarize links               │
└───────────────────────────────┘
```

Это особенно интересно для сложных productivity extensions.

---

# Почему keyboard-driven UX эффективен

Если пользователь часто повторяет:

```text
open extension
click button
select action
close popup
```

это становится дорогим взаимодействием.

Keyboard shortcut сокращает:

```text
5 interactions
```

до:

```text
1 interaction
```

---

# Но shortcuts нельзя делать слишком многочисленными

Плохой keyboard UX:

```text
Ctrl+Shift+A
Ctrl+Shift+B
Ctrl+Shift+C
Ctrl+Shift+D
Ctrl+Shift+E
Ctrl+Shift+F
...
```

Пользователь не сможет это запомнить.

Хороший UX имеет небольшое количество основных shortcuts:

```text
Open
Search
Analyze
Save
Toggle
```

а остальные действия доступны через command palette или UI.

---

# Hierarchical commands

Для большого extension можно организовать команды логически:

```text
Extension
│
├── Open
│
├── Analyze
│   ├── Page
│   └── Selection
│
├── Save
│   ├── Page
│   └── Selection
│
└── Search
```

При этом manifest commands могут содержать только наиболее важные shortcuts.

---

# Commands как accessibility mechanism

Keyboard shortcuts полезны не только power users.

Они могут улучшить accessibility.

Некоторые пользователи предпочитают:

```text
keyboard
```

вместо:

```text
mouse
```

Поэтому хороший extension должен предоставлять логичные keyboard interactions там, где это действительно полезно.

---

# Commands и focus

Особенно важно учитывать, где находится keyboard focus.

Пользователь может печатать:

```text
<input>
```

и одновременно нажать комбинацию.

Extension не должен неожиданно ломать стандартное поведение страницы.

Поэтому shortcuts должны быть:

* редкими;
* хорошо выбранными;
* предсказуемыми;
* не конфликтующими с привычными действиями.

---

# Не hijack обычные browser shortcuts

Не стоит пытаться заменить:

```text
Ctrl+L
Ctrl+T
Ctrl+W
Ctrl+R
Ctrl+F
```

обычными extension workflows.

Browser shortcuts являются частью базовой модели браузера.

Extension commands должны дополнять её, а не конкурировать с ней.

---

# Command naming

Используйте семантические имена:

```text
open-panel
analyze-page
save-selection
toggle-feature
search-extension
```

а не:

```text
ctrl-shift-a
button-1
do-action
command-2
```

Shortcut может измениться.

Semantic command должен оставаться стабильным.

---

# Command Protocol

Для большого extension можно представить command как структуру:

```javascript
{
    type: "ANALYZE_PAGE",
    source: "keyboard",
    context: {
        tabId: 123
    }
}
```

Это уже не просто browser event.

Это application command.

---

# Command Bus

Можно построить:

```text
                         Command Sources
                              │
             ┌────────────────┼────────────────┐
             ▼                ▼                ▼
         Keyboard           Popup           Side Panel
             │                │                │
             └────────────────┼────────────────┘
                              ▼
                         Command Bus
                              │
             ┌────────────────┼────────────────┐
             ▼                ▼                ▼
         Analyzer          Storage          Navigation
```

Это очень масштабируемая архитектура.

---

# Commands и Emerge

В архитектуре Web Platform-first framework commands можно рассматривать как ещё один native event source:

```text
HTML Events
      │
      ├── click
      ├── input
      └── submit
            │
            ▼
        Emerge

Browser Extension Events
      │
      ├── commands
      ├── tabs
      ├── alarms
      └── runtime
            │
            ▼
        Extension Runtime
```

Emerge/application layer может унифицировать обработку событий на уровне приложения, но не должен скрывать фундаментальную модель Manifest V3.

# Production example

Представим extension **Page Researcher**.

Он имеет три shortcuts:

```text

    Analyze page

Ctrl+Shift+S
    Save selection

Ctrl+Shift+P
    Open research panel
```

Manifest:

```json

    "manifest_version": 3,

    "name": "Page Researcher",
    "version": "1.0.0",

    "permissions": [
        "activeTab",
        "scripting",
        "storage",
        "sidePanel"
    ],

    "background": {
        "service_worker": "service-worker.js"

        "analyze-page": {

        "save-selection": {
```

# Service Worker

```javascript
chrome.commands.onCommand.addListener(
    async (command) => {

        switch (command) {

            case "analyze-page":
                await analyzePage();
                break;

            case "save-selection":
                await saveSelection();
                break;

            case "open-panel":
                await openPanel();
                break;
        }
    }
);
```

# Analyze

```javascript
async function analyzePage() {

    const [tab] =
        await chrome.tabs.query({
            active: true,
            currentWindow: true
        });

    if (!tab?.id) {
        return;
    }

    await chrome.scripting.executeScript({
        target: {
            tabId: tab.id
        },
        func: () => {

            const title =
                document.title;

            const text =
                document.body.innerText;

            console.log({
                title,
                text
            });
        }
    });
}
```

В реальном production-приложении обработку результатов лучше отделить от самого injection call и передавать их через application protocol.

# Open panel

```javascript
async function openPanel() {

    const [tab] =
        await chrome.tabs.query({
            active: true,
            currentWindow: true
        });

    if (!tab?.windowId) {
        return;
    }

    await chrome.sidePanel.open({
        windowId: tab.windowId
    });
}
```

# Главные принципы главы

### 1. Command — это semantic action

```text
analyze-page
```

а не:

```text
Ctrl+Shift+A
```

---

### 2. Shortcut — configuration

Пользователь может изменить его.

---

### 3. Command handler должен быть небольшим

```text
Command
 ↓
Router
 ↓
Application Service
```

---

### 4. Service Worker — естественное место обработки commands

```text
Browser event
     ↓
Service Worker
```

---

### 5. Context должен определять действие

```text
Command
   +
Current context
   ↓
Action
```

---

### 6. Commands могут запускать любой extension workflow

Например:

```text
Command
 ↓
Content Script
```

или:

```text
Command
 ↓
Side Panel
```

или:

```text
Command
 ↓
Storage
```

или:

```text
Command
 ↓
Tabs
```

---

### 7. Не создавайте shortcut для каждого действия

Используйте shortcuts для наиболее частых операций.

---

### 8. Для сложных extensions используйте Command Bus

```text
Keyboard
Popup
Side Panel
Content Script
       │
       ▼
 Command Bus
       │
       ▼
Application
```

# Итог

Commands превращают браузерное расширение из приложения, управляемого преимущественно мышью, в приложение с полноценным **keyboard interface**.

Базовая цепочка выглядит так:

```text
Keyboard
   ↓
Shortcut
   ↓
Command ID
   ↓
Service Worker
   ↓
Command Handler
   ↓
Application Logic
```

А в сложном extension:

```text
                         Keyboard
                            │
                            ▼
                         Command
                            │
                            ▼
                    Service Worker
                            │
             ┌──────────────┼──────────────┐
             ▼              ▼              ▼
       Content Script   Side Panel       Storage
             │              │              │
             ▼              ▼              ▼
           Page             UI         App State
```

Самое важное — **не привязывать архитектуру к конкретной клавиатурной комбинации**.

`Ctrl+Shift+A` может завтра стать другой комбинацией. Но смысл:

```text
analyze-page
```

останется тем же.

Поэтому зрелая архитектура Manifest V3 рассматривает Commands не как «горячие клавиши», а как **semantic entry points в application runtime**. Именно такой подход позволяет затем объединить keyboard shortcuts, Action, Popup, Side Panel и Content Scripts через единый command/event architecture.
